# RAG / Game Master Contract (version 1)

What the backend expects from the separately developed PDF-grounded question service
("game master"), and what it promises in return. The backend is the only caller; the
frontend never talks to this service, and this service never touches player state.

**Status:** no game master exists in this repository yet. This contract is implemented by the
backend's client (`backend/src/learning_game_backend/rag/`) and verified against a mock
transport (`backend/tests/contract/test_rag_contract.py`) and a fake provider. It has **not**
been exercised against a real pipeline.

## Responsibilities

| The game master does | The game master does NOT |
|---|---|
| Ingest a PDF and make it searchable | Know about players, accounts, XP, health, or battles |
| Retrieve only from the document IDs in the request | Decide rewards, penalties, costs, unlocks, or outcomes |
| Generate questions, answers, explanations, difficulty 1–5, and source pages | Grade player answers (the backend does, with the key it receives) |
| Return structured JSON as specified below | Receive player answers or identities |

Any extra fields it returns (for example `"xp_reward": 10000`) are ignored. Every set it
returns is validated before use; one invalid question rejects the whole set.

## Transport

- Base URL from `GAME_MASTER_URL`. Version prefix `/v1`. JSON bodies, UTF-8.
- If `GAME_MASTER_API_KEY` is set, requests carry `Authorization: Bearer <key>`.
- The backend times out after `GAME_MASTER_TIMEOUT_SECONDS` (default 60) per request and
  does **not** retry automatically. A timeout fails that job with a visible message.
- IDs the backend sends (`document_id`, `question_set_id`) are 32-character lowercase hex
  strings generated by the backend. Treat them as opaque.

## `POST /v1/documents`: ingest a PDF

`multipart/form-data` with fields `file` (the PDF bytes) and `document_id`.
Return when the document is searchable (the backend waits for the response).

Success:

```json
{ "status": "ready" }
```

Ingestion failed (user-visible reason, at most 200 characters):

```json
{ "status": "failed", "error": "The PDF contains only scanned images." }
```

Anything else (another `status`, HTTP ≥400, a timeout, or invalid JSON) marks the document
`failed` for the player.

## `POST /v1/question-sets`: generate questions

Request:

```json
{
  "contract_version": 1,
  "question_set_id": "0f3c9a5e7b1d4c2a8e6f0a1b2c3d4e5f",
  "document_ids": ["a1b2c3d4e5f60718293a4b5c6d7e8f90"],
  "topic": "Mitochondria",
  "mode": "practice",
  "count": 5,
  "difficulty_min": 1,
  "difficulty_max": 5
}
```

`mode` is `practice` or `adventure`. `count` is 1–50. Return **at most** `count` questions
within the requested difficulty range where possible. Retrieve only from `document_ids`.

For the current minimal campaign, an adventure request with `count: 3`,
`difficulty_min: 1`, and `difficulty_max: 5` must return exactly three questions at
difficulties 1, 3, and 5. The backend reserves those exact levels for the Forest Goblin,
Bridge Troll, and Castle Dragon; a missing level prevents that encounter from starting.

Response:

```json
{
  "schema_version": 1,
  "generation": {
    "provider_question_set_id": "gm-77",
    "model": "example-model",
    "prompt_version": "p7",
    "pipeline_version": "2.1",
    "generated_at": "2026-10-24T18:00:00Z"
  },
  "questions": [
    {
      "id": "q-001",
      "type": "numeric",
      "mode": "practice",
      "topic": "Mitochondria",
      "learning_objective": "Count human chromosomes",
      "prompt": "How many chromosomes does a human cell contain?",
      "answer": { "value": 46 },
      "grading": { "tolerance": 0 },
      "explanation": "Humans have 23 pairs of chromosomes.",
      "difficulty": 3,
      "sources": [{ "document_id": "a1b2c3d4e5f60718293a4b5c6d7e8f90", "pages": [4, 5] }]
    },
    {
      "id": "q-002",
      "type": "multiple_choice",
      "prompt": "Which organelle produces most of the cell's ATP?",
      "options": [
        { "id": "A", "text": "Nucleus" },
        { "id": "B", "text": "Mitochondrion" }
      ],
      "answer": { "option_id": "B" },
      "explanation": "Mitochondria produce most of the cell's ATP.",
      "difficulty": 2
    }
  ]
}
```

### Field rules (enforced by `rag/validation.py`)

| Field | Rule |
|---|---|
| `schema_version` | Must be `1` |
| `questions` | Non-empty list, no more than `count` items |
| `id` | Required, unique within the set, up to 200 characters. Stable for the same question |
| `type` | `numeric` or `multiple_choice` |
| `mode` | Optional; if present must equal the requested mode |
| `topic` | Optional (defaults to the requested topic), up to 200 characters |
| `learning_objective` | Optional, up to 200 characters |
| `prompt`, `explanation` | Required, non-empty, up to 4000 characters. Treated as plain text |
| `difficulty` | Whole number 1–5. Booleans, floats, and strings are rejected |
| `answer` (numeric) | `{"value": n}`, a finite number or numeric string |
| `grading.tolerance` | Optional, numeric only, `>= 0`, default `0` (exact match) |
| `options` | Multiple choice only: 2–6 items; `id` is 1–32 of letters, digits, `_`, `-`, unique |
| `answer` (multiple choice) | `{"option_id": id}` naming one of the options |
| `sources[].document_id` | Must be one of the requested documents |
| `sources[].pages` | Optional list of positive integers. **If you do not supply pages, none are shown. They are never invented** |
| `generation` | Only `provider_question_set_id`, `model`, `prompt_version`, `pipeline_version`, `generated_at` are kept (up to 200 characters each) |

### What the backend does with the result

1. Validates the whole set. On any violation the set is stored as `failed` with a message
   naming the first problem, and nothing from it becomes playable.
2. Stores every accepted question, including the private answer key, **before** any player
   sees it. The backend assigns its own question IDs; your `id` is kept as
   `source_question_id`.
3. Never regenerates a question. A pending attempt always shows the stored one.

## Errors

Return an HTTP status of 400 or higher, optionally with a short message:

```json
{ "error": "Topic not found in the selected documents." }
```

The backend shows at most the first 200 characters of `error` to the player, replaces a
missing or non-text value with a generic message, and never forwards raw bodies, URLs, or
keys. Keep `error` safe to display.

| Situation | Player sees |
|---|---|
| Timeout | "The game master did not respond within N seconds." |
| Cannot connect | "The game master could not be reached." |
| HTTP ≥400 with `{"error": "..."}` | That message (truncated) |
| HTTP ≥400 otherwise | "The game master returned HTTP 502." |
| Invalid JSON | "The game master returned invalid JSON." |
| Contract violation | "question 2: 'difficulty' must be a whole number from 1 to 5." |

## No fallback

If the real provider fails, the job fails. The backend never substitutes fake or packaged
questions. `GAME_MASTER_MODE=fake` must be set explicitly, is labelled `fake` in API
responses, and its questions are **not** generated from the PDF.

## Changing the contract

Add a new `contract_version`, keep the old one working until every deployment has moved,
update `rag/validation.py` and its tests, and update this file in the same change.
