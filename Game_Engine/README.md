# Learning Game Engine

The pure rules of the learning game: XP, health, the permanent adventure unlock, villain
order, paid battles, and attempt tracking. It is a small Python package with **no runtime
dependencies**: no web framework, database, HTTP client, PDF library, authentication, or RAG
code. Hosts (such as the [backend](../backend/)) supply the questions, decide whether an
answer was right, and store the state; the engine decides what that means.

## What it owns

- Immutable player state (`PlayerState`) and a new state for every change.
- XP and health rules, including clamping at zero and the early end of a battle at zero health.
- Adventure unlocking, lesson and practice positions, villain order and completion.
- Battle entry validation and charging exactly once; battle attempts.
- Applying an already-evaluated `true`/`false` outcome.
- Duplicate-attempt protection and state invariants.
- Pure serialization of state to dictionaries (`state_codec.py`; no files or databases).

It does **not** own routes, accounts, databases, PDFs, RAG, question validation, grading of
raw answers, CORS, or response schemas.

## Use

```python
from learning_game_engine.engine import GameEngine
from learning_game_engine.models import Scene

engine = GameEngine.new_game("Ada", slide_count=3, villain_ids=["a", "b", "c"])
engine.go_to(Scene.PRACTICE)

# The host supplies the question ID and its stored difficulty.
pending = engine.present_practice_question("q-1", difficulty=3)

# The host decides whether the answer was right; the engine applies the rules.
result = engine.submit_practice_result(pending.attempt_id, correct=True)
print(result.xp_delta, result.health_delta)  # 20 0 (health was already full)

new_state = engine.state  # frozen; store it however you like
```

Every action validates first and raises `InvalidAction` without changing anything, or
replaces the whole state at once. `correct` must be a real `bool`.

## Layout

```text
Game_Engine/
├── pyproject.toml          name learning-game-engine; dependencies = []
├── uv.lock
├── src/learning_game_engine/
│   ├── rules.py            every number: XP table, health, costs, validation
│   ├── models.py           frozen dataclasses and enums (state, attempts, results)
│   ├── engine.py           GameEngine: actions, transitions, validate_state
│   ├── state_codec.py      PlayerState <-> plain dict, with structural checks
│   └── py.typed
└── tests/                  fast, no files / databases / network
    ├── test_engine.py      rules and invariants, plus the import-isolation tests
    ├── test_rules.py       defaults and rule validation
    ├── test_models.py      immutability and derived values
    └── test_state_codec.py round trips and rejection of malformed data
```

Reading order: `rules.py` → `models.py` → `engine.py` (actions, then `validate_state`) →
`state_codec.py`. Dependencies between modules: `engine` → `models`, `rules`;
`state_codec` → `models`, `rules`; `models` and `rules` import nothing.

## State, attempts, and persistence

`state_codec.state_to_dict` / `state_from_dict` define the serialized shape (format version
`2`). Fields: `format_version`, `player_name`, `scene`, `xp`, `health`, `adventure_unlocked`,
`lesson_position`, `lesson_completed`, `practice_position`, `pending_practice`,
`completed_villains`, `active_battle`, `processed_attempt_ids`. `state_from_dict` checks
structure and types and raises `StateCodecError`; `GameEngine(state, ...)` then checks the
invariants and raises `InvalidState`. Referenced content IDs are not checked: the engine owns
no content, so the host must (the backend checks them against its stored questions).

Three kinds of identifier: a *question ID* (reusable content, supplied by the host), a
*question attempt ID* (one presentation, answerable once, generated by the engine), and a
*battle attempt ID* (one paid battle). A processed attempt ID is rejected if submitted again.

## Invariants (`validate_state`)

Non-blank name; `xp >= 0`; `0 <= health <= max_health`; positions in range; XP at or above the
unlock threshold implies unlocked; completed villains are a prefix of the villain order;
the battle scene holds exactly when a battle is active; an active battle is against the next
undefeated villain, needs health above zero, has the right question count with difficulties
1–5, `correct_count <= position`, and an unprocessed pending attempt.

## Change recipes

| Change | Where |
|---|---|
| Any XP, health, or cost number | `rules.py` (then update expected values in tests) |
| How an action behaves | the matching method in `engine.py`, with a test in `test_engine.py` |
| A persisted field | `models.py`, `GameEngine.new_game`, an invariant in `validate_state`, `state_codec.py` (bump `STATE_FORMAT_VERSION`), then every host's stored data (the backend's `player_states.state_json`) |
